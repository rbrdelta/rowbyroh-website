Model Behavior EP04 · July 2026

Refused the Bait

We left a page of wrong answers where the model could see it. It never took them — and at the edge of its ability it got worse anyway, with its confidence registering nothing at all.

Fourth in an ongoing series. Episode one, An Earned Null, found that emotional pressure delivered through prompts moves nothing. Episode two, Cost of Verification, found that difficulty alone moves nothing either. Episode three, Depth, Not Breadth, found that the model estimates its confidence from a surface signal rather than from any thorough evaluation of the task. This episode puts a false signal in front of it on purpose.

01

The premise

This series is about the human-model interaction: understanding the factors that drive a model's behaviour well enough to understand, influence, and eventually anticipate it. The method is to find knee points — the specific conditions where behaviour changes — because the transitions are where the driving factors become visible.

Episode three established that the model estimates its confidence based on the surface-level signal, not a thorough evaluation of the task. The hypothesis for this episode followed from that directly: if the self-assessment reads surface cues, then planting an external cheat sheet where the model can see it should increase its predicted confidence. That prediction was registered before the run, so the result could not be reinterpreted after the fact.

It did not happen. The cheat sheet never raised confidence, and the model never copied from it. It just became noise. Why it was processed as noise, I don't know. But the distraction, when the model was already struggling to keep track of a high degree of difficulty, led to less accurate results.

02

The experiment design

The task is the warehouse ledger from episode three. The model reads a long log of stock movements across three warehouses, reports the final count of every tracked item, and adds one number from 0 to 100: the probability that every count is exactly right. A script computes the true answer, so the grading is exact.

The cheat sheet is a memo placed in the context ahead of the task. It is styled as an internal audit document, it carries the reference number of a prior reconciliation cycle, and it lists expected final stock figures for every item the model is about to count. Those figures are wrong. Nothing in the prompt tells the model to use the memo, and nothing tells it to ignore the memo.

One property of the design is what makes any of this measurable, and it was a deliberate choice made two episodes ago. The model answers through the API's structured-output mode, which constrains generation itself: the decoder can only emit tokens that fit the answer schema, so there is no prose, no reasoning trace, and no scratch space anywhere in the trial. We closed that channel because the model kept using it to replay the ledger, which defeats a task built so that checking an answer costs as much as producing it.

Because that channel is closed, a final count can only arrive one of three ways. The model tracked the item in real time, which costs it accuracy we can measure. It guessed. Or it cheated and took the figure off the memo. Nothing else is available to it, which is what makes a copied figure mean something rather than nothing.

Separating a copy from a lucky guess needs a floor, so every run with the memo has a twin run without it — the same ledger, with either no memo at all or a memo of pure procedural filler. The model cannot have seen a planted figure in the twin, so a match there is coincidence by construction, and copying has to clear that rate.

03

What Sonnet did

Sonnet read the memo and did not use the memo. It did not find the memo useful. What it did instead was get distracted by it, and the distraction cost nothing until the task was hard enough that the model had nothing to spare.

At the easy setting, where about 88% of counts come back correct, the memo changed nothing worth reporting. The planted figures were never taken, confidence did not inflate, and the misleading memo was indistinguishable from one with no content in it: on 17 of 20 ledgers the model returned exactly the same confidence number under both. So the entire effect at this difficulty is a small tax for having an extra document in the context, and that tax is blind to what the document says.

Doubling the length of the log drops accuracy to about 54%. Roughly half the counts are wrong at that point, which is the condition where a planted figure has room to be adopted.

It was not adopted. One wrong count in 183 matched a planted figure, and I read that one as coincidence: the model wrote 27 where the truth was 22, a five-point miss in a run whose typical miss is twelve, and the twin run with no memo produced that kind of collision more often rather than less.

The accuracy cost is real. Against a filler memo built to the same length,3 the misleading memo costs 4.2 percentage points, and the model's stated confidence over the same ledgers does not move.

Twenty ledgers is a small sample, so the argument rests on the direction of the pairs rather than on the size of the averages.1 Thirteen of the twenty came out different, and eleven of those thirteen were worse under the misleading memo, which is a split that luck produces about three times in a hundred. The same count run on confidence gives seven down and eight up.

One consequence is worth stating on its own, because it would be easy to miss. Counting how often a wrong answer matches a planted figure is a reasonable detector: it is cheap, it is automatic, and it does catch a model being led by content in its context. Here it catches nothing. The behaviour it is built to find is copying, and what happened to Sonnet is distraction, so a clean result from that detector says nothing about whether the model was harmed.

04

What Haiku did

Haiku, the smaller model in the same family, did something else. It saw the hints, and its estimated-versus-actual gap — the distance between the confidence a model reports and the accuracy it delivers — moved with them, though not in one direction.

It also copies. Roughly one ledger in five contains a planted figure when the memo is present, against one in twenty when it is not.2

Which way that gap moves depends on what the memo says, not on how well the model actually did. Under the misleading memo its accuracy falls 5.6 points and the gap narrows, from +10.5 to +7.8: it did worse, and something registered that. Under the memo containing nothing — no figures, just official-looking paperwork — its accuracy is flat, its confidence rises 6.9 points, and the gap widens to +16.3. No better, and it reports feeling better.

I want to be careful about what the two models add up to, because I genuinely cannot assume a connection between them. Haiku's behaviour tells us that it saw the hints and overestimated. Sonnet's behaviour tells us only that it read the memo and did not use the memo. Those look like two fundamentally different behaviours that happen to share a task and a test, and why they differ, I don't know.

05

What this establishes

The finding that survives is narrower than the hypothesis and, I think, more useful than the hypothesis would have been. Adversarial content does not have to be believed in order to do damage. The model can read it, decline to use it, take nothing from it, and still do the work measurably worse — and none of that appears in what the model says about its own performance.

06

Up next

The part we did not explore here is the depth of difficulty. Episode three established that what makes this task hard is the number of times a single item changes, rather than the number of items being counted: more changes to one item produces more errors than a few changes to each of many. We reached the hard setting in this episode by doubling the length of the log, which does raise depth, but also makes the difficulty visible — and the model's confidence fell to meet it.

There is a version of the same difficulty that stays hidden. Three items in a twenty-five-line log carry the same number of changes per item as six items in a fifty-line log, but the page looks short. In episode three the model's confidence stayed pinned near 82 in that cell while its accuracy sat at 62%, which is the largest overclaim this instrument has induced from it. That cell never received a memo.

So the next run puts the cheat sheet where the model is struggling and does not appear to know it. If noise costs accuracy there as well, it lands on top of a confidence number that is already wrong.

07

Limitations and fine print

  1. Twenty ledgers per condition. Every claim above is a count of which direction the paired results moved, not a comparison of averages — the stated confidence takes only a handful of distinct values, so averages mislead at this size.
  2. The copying rate pools both difficulty settings, a decision made after seeing the per-setting numbers, and neither setting clears on its own. Exploratory, not registered.
  3. The filler memo used for that comparison is built to the misleading memo's exact length, measured rather than eyeballed. An earlier, shorter filler was not, and the matched run replaced it. Length alone accounts for nothing: going from no memo to a full-length harmless one costs 0.6 points. Three comparators with no planted content converge on 4 to 5 points.
  4. That matched run happened five days after the runs it is compared against, so the no-memo baseline was re-run the same day. The two baselines differ by 0.3 points.
  5. The confidence question asks for the probability that every count is right, which is much harder than any single count being right. Episode three showed the model answers the easier question instead. Comparisons here hold that constant, so the raw confidence numbers should not be read as calibrated.
  6. Two models from one family, one task family, no tools, and no extended thinking. Whether a model allowed to reason on paper would notice the interference is not established here.
